    Enviar uma imagem¶

    Três imagens podem ocupar a tela Imagens do app (as setas < > navegam entre elas). O caminho abaixo não usa wine: parte de um .acf que o firmware já aceita e troca só os bytes das texturas.

    Primeiro: tenha um template¶

    O template é um .acf válido, gerado uma vez (por firmware/screen). Normalmente já existe:

    ~/.local/share/minitela-custom/out/minitela.acf

    Se não existir, gere com o compilador (só nesta etapa o wine entra):

    ./minitela_build.py setup
./minitela_build.py build ~/alguma_foto.jpg

    Sem template nenhum (nem wine, nunca)¶

    O próprio tema de fábrica serve de base. Ele tem os três slots em 192×192 (o template compilado por nós usa 240×240):

    ./minitela_patch.py --template /usr/share/minitela/resources/ACF/Texture.acf \
                    --out ~/minha.acf ~/foto.jpg --send

    Só o Texture.acf (o tema padrão) funciona como base — os Texture1..21.acf não têm as três texturas de imagem nas páginas 4/5/6.

    Tamanho: slot (192) ou tela cheia (240)¶

    Padrão: a imagem é gravada no tamanho do slot — 192×192 no tema de fábrica. O widget tem 240 e aplica escala 1,25, então a imagem enche a tela já ampliada.

    Tela cheia de verdade (240×240): use --tela-cheia. Ele grava a textura em 240 e ajusta o que anda junto no registro: SingleSliceSize, largura/altura, o escalonador (640 → 512, ponto fixo 1.9) e os tile boxes. Sem esse ajuste a textura 240 é ampliada 1,25× e corta — só aparece o canto superior esquerdo (foi assim que descobrimos o acoplamento).

    ./minitela_patch.py --template /usr/share/minitela/resources/ACF/Texture.acf \
                    --out ~/minha.acf --tela-cheia ~/foto.jpg --send

    Testado no hardware: imagem de teste com moldura e letras nos quatro cantos aparece inteira, sem wine. As três imagens em 240 dão um arquivo de 901.128 B — o mesmo tamanho do template compilado pelo fabricante.

    Trocar as imagens¶

    # 1 imagem (os outros slots ficam como no template)
./minitela_patch.py --template ~/.local/share/minitela-custom/out/minitela.acf \
                    --out ~/minha.acf ~/foto.jpg

# 3 imagens
./minitela_patch.py --out ~/minha.acf ~/a.jpg ~/b.png ~/c.gif

# e gravar
./minitela_patch.py --out ~/minha.acf ~/a.jpg --send

    O que ele faz, em ordem:

    1. recorta no centro e escala para o tamanho da textura (240×240 no template compilado);
    2. converte para o formato de bloco do chip (STC, blocos 4×4 de 16 B);
    3. escreve nos offsets da tabela de texturas;
    4. valida com o acf_inspect.py — magic, versão e o CheckCode de todas as páginas;
    5. só então grava.

    Se a validação falhar, ele não grava nada.

    Depois de gravar¶

    Abra o app pelo botão dedicado do teclado e vá até a tela Imagens. Se ela não aparecer ao passar pelo botão, pode estar desabilitada — ligue "Imagens" na lista de telas, ou:

    gsettings set org.policorp.minitela saved-screens "[true,true,true,true,true,true,true]"

    Conferir sem gravar¶

    ./acf_inspect.py --textures ~/minha.acf | head -20   # lista as texturas
./acf_inspect.py --diagnostico ~/minha.acf           # explica o que quebrou, se quebrou

    Você vê as páginas, o número de texturas e, com --textures, cada textura com tipo, dimensão e endereço.

    Voltar ao original¶

    pkill -x minitela
./minitela_ctl.py send /usr/share/minitela/resources/ACF/Texture.acf -y

    Por que isso é seguro

    As texturas ficam antes da configuração do arquivo (que começa em StartOfConfigdata), e o firmware só valida o checksum de cada bloco de página. Trocar textura não invalida nada; o resto do .acf continua byte a byte idêntico. Detalhe em RE-acf.md.
